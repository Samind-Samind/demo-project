  - ถามผู้ใช้เพิ่มเติม 4 ประเด็น ได้คำตอบ: แบ่งสิทธิ์การเข้าถึงหลายระดับ, เลือกช่วงเวลาดูข้อมูลเองได้ (วัน/สัปดาห์/เดือน), ต้องการรายละเอียดเต็มรูปแบบ (กราฟ, แยกตามเมนู/โต๊ะ), ต้อง export/พิมพ์เป็น PDF ได้

- สร้างเอกสาร requirement ใหม่ [[../01-requirements/01-spec/20260802-003-audit-log-pdpa|ระบบเก็บ Audit Log และการปฏิบัติตาม PDPA]] จาก requirement ดิบ "เพิ่มระบบเก็บ log (audit log) และการปฏิบัติตาม PDPA ในระบบ My Coffee Store"
  - ตรวจสอบเอกสารเดิม ([[../01-requirements/01-spec/20260802-001-table-self-order|Table Self-Order]] และ [[../01-requirements/01-spec/20260802-002-sales-dashboard|Sales Dashboard]]) แล้วพบว่าเป็นหัวข้อ cross-cutting (audit/security/compliance) คนละเรื่องกับ feature เดิม จึงสร้างเอกสารใหม่แยกต่างหาก พร้อมใส่ลิงก์อ้างอิงกลับไปยังทั้งสองเอกสาร แทนที่จะแก้ไขเอกสารเดิม
  - requirement ดิบที่ผู้ใช้ระบุมาค่อนข้างชัดเจนแล้วในหลักการสำคัญ (เน้น audit log ฝั่งพนักงาน/แอดมิน, consent แบบง่ายเท่าที่จำเป็น, ไม่ทำ consent management ซับซ้อน) จึงไม่ได้ถามคำถามเพิ่มเติมกับผู้ใช้ แต่ตัดสินใจเองในประเด็นที่ไม่ได้ระบุตัวเลขชัดเจน 2 เรื่อง โดยบันทึกเหตุผลไว้ในเอกสารด้วย: (1) ระยะเวลาเก็บ log (retention) กำหนดที่ 12 เดือนแล้วลบอัตโนมัติ อิงหลัก data minimization ของ PDPA, (2) สิทธิ์เข้าถึง log จำกัดเฉพาะเจ้าของร้าน/ผู้จัดการ ให้สอดคล้องกับ role-based access ที่มีอยู่แล้วใน Sales Dashboard
  - อัปเดต [[../01-requirements/01-spec/index|01-spec/index]] เพิ่มลิงก์ไปเอกสารใหม่
  - อัปเดต [[../01-requirements/backlog|01-requirements/backlog]] เพิ่มแถวสำหรับ requirement นี้
